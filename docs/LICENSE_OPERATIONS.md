# 许可证运营 SOP（License Operations）

> 面向：发行方商业运营 / 客户成功 / 技术支持。
> 目标：把"签许可证"变成**每月可重复、可审计、出事有预案**的运营流程。
> 技术细节见 `docs/COMMERCIAL_ACTIVATION.md`；本文只讲"人怎么干活"。
>
> 版本：v1.11.18（许可证协议 v3 / 批量发证 / 台账 / CRL / 机器绑定 / 周期复检；licensing CLI 与 v1.11.15 一致，v1.11.18 未改动 licensing 协议与运营流程）。

---

## 0. 一句话流程

```
签约 → 填客户 CSV → issue-batch 出证 + 台账 → 交付 .ampkg
     → 客户拖包激活 → 每月巡检台账（到期/绑定/吊销）→ 续期或吊销
```

所有操作在**发行方内网**完成；许可证离线可用，不需要客户联网、不需要联网授权服务器。

---

## 1. 角色与权限

| 角色 | 能做什么 | 不能做什么 |
|---|---|---|
| 发行运营 | 读台账、`issue-batch`、`bundle`、`revoke`、`crl` | 触碰私钥、改 keys.py |
| 发行技术 | `keygen` / `doctor` / 构建 wheel / 轮换密钥 | 把私钥贴进工单或聊天 |
| 客户 IT | 拖入 `.ampkg` / 粘贴许可证 / 提供本机指纹 | 生成许可证 |
| 客户成功 | 读台账（脱敏视图）、到期提醒、解释失败原因 | 直接改 CRL |

纪律：

- 台账与 CRL 都放在 `dist/`（`.gitignore` 内），**不进 git、不进公开网盘**；
- 私钥只存在于发行方离线环境；运营同学**不需要**也不应该接触私钥；
- 每个客户一个 `serial`；没有序列号的 v2 证用"派生序列号"（`sha256(许可证)[:12]`），
  工具会自动算，不用手工。

## 2. 月度巡检清单（每月 1 号，约 15 分钟）

### 2.1 发行环境自检

```bash
python pro/tools/issue_license.py doctor
```

任一项 `ok=false` 立即停发并升级到发行技术。重点看：

| 检查项 | 含义 | 处理 |
|---|---|---|
| `keypair_matches` | 私钥与公钥配对 | 不配对=签出来的证客户全验不过，**立即停发** |
| `wheel_public_key_matches` | wheel 内公钥=keys.py | 不一致=客户装上激活不了，重建 wheel |
| `key_rotation_state` | 是否处于换钥过渡期 | 看到"过渡期"就顺手排换证计划 |
| `crl_readable` | CRL 是否可读 | 坏了会误放行已吊销的证 |
| `license_recheck_config` | 复检是否开启 | 显示 `0s` 说明复检被关，长驻进程不再自动降级 |

### 2.2 台账巡检

打开 `<out>/license_ledger.csv`（可用 Excel/WPS），逐项核对：

1. **到期 30 天内**的客户 → 提前发续费提醒（话术见 §4.2）；
2. **到期已过 7 天**仍未续费 → 确认是否已降级，必要时吊销；
3. `machine` 列非空且客户报"激活失败" → 核对是否换了机器（§3.2）；
4. `serial` 是否连续、无重复（重复说明批量 CSV 写错，可能导致吊销误伤）；
5. `sha256` 与客户收到的包是否一致（客服核对交付物完整性）；
6. 新增客户是否都进了台账（对照合同清单）。

### 2.3 CRL 巡检

```bash
python pro/tools/issue_license.py crl list
```

- 确认已吊销的客户**已收到**带 CRL 的升级包 / CRL 文件（离线吊销不会自动生效）；
- CRL 文件体积过大（>1000 条）时考虑按批次归档，但**不要删条目**——
  删除等于恢复授权，必须走审批。

### 2.4 月度输出（留档）

- 本月发证数 / 续期数 / 吊销数 / 失败行数；
- 到期客户清单（客户、到期日、序列号、负责人）；
- `doctor` 输出 JSON 存档（证明发证链路健康）。

## 3. 常见客户操作

### 3.1 新客户激活（1 分钟）

1. 收到 `.ampkg` → 打开 AutoMind → 设置 →「⭐ 升级专业版 / 企业版」；
2. 把 `.ampkg` 拖进「⚡ 一键升级」；
3. 看到"已升级为专业版 / 企业版"即完成；若提示重启，重启一次后自动激活
   （许可证已提前保存，不会丢）。

无法拖入时的保底路径：

```bash
pip install automind_pro-<ver>-py3-none-any.whl        # 或面板拖 .whl
# 把许可证写到 ~/.automind/license（一整行 AMP2-...），或设置 AUTOMIND_LICENSE
```

### 3.2 换机 / 迁移

客户 IT 步骤：

1. 新机器打开升级面板 → "本机信息"卡片 → **复制本机指纹**（16 位 hex）发给发行方；
2. 发行方按新指纹重发绑定证：

```bash
python pro/tools/issue_license.py bundle PRO 20281231 acme \
    --machine <新机器指纹> --serial ACME20260001 \
    --wheel pro/dist/automind_pro-<ver>-py3-none-any.whl --out dist/upgrades
```

3. 客户在新机器拖入新包；旧机器上的旧证可继续用到到期，若旧机器已处置则先吊销。

> 提醒客户：重装系统/清空用户目录会改变本机指纹（安装盐变化），
> 因此**换系统盘前先报备**，避免激活失效。

### 3.3 续期

```bash
python pro/tools/issue_license.py bundle PRO 20281231 acme \
    --serial ACME20260001 --machine <客户指纹> --out dist/upgrades
```

客户拖入新包即可覆盖旧证，无需卸载、数据不丢。
提前续约可加 `--start 20270101`（到生效日前旧证继续用，新证不会提前生效）。

### 3.4 到期/宽限/降级客户会看到什么

| 状态 | 客户看到 | 客服解释 |
|---|---|---|
| 过期（宽限=0） | 降级社区版，商业功能 🔒；升级面板显示"许可证已过期" | 续费后拖入新包即恢复 |
| 宽限期内 | 仍可用，面板红色提示"宽限期剩余 N 天" | 请尽快完成续费 |
| 超出宽限 | 降级社区版 | 同过期 |
| 机器不符 | "许可证绑定的机器与本机不符（本机指纹 X，绑定 Y）" | 换机需重发绑定证 |
| 被吊销 | "许可证已被吊销" | 转商务处理，不解释内部原因 |
| 时钟回拨 | "检测到系统时钟回拨" | 让客户校正系统时间（NTP）后重试 |

## 4. 客服话术模板

### 4.1 发证交付

> 您好，贵司的 AutoMind 专业版（/企业版）许可证已生成。附件是升级包
> `AutoMind-PRO-<客户>-<到期日>.ampkg`，请转交 IT 同事：
> 打开 AutoMind → 左下角「设置」→「⭐ 升级专业版 / 企业版」→ 把附件拖进
> 「⚡ 一键升级」区域即可，全程不需要安装 Python、不需要联网。
> 若提示需要重启，重启一次 AutoMind 后会自动完成激活。

### 4.2 到期前提醒（提前 30 / 7 天）

> 您好，贵司 AutoMind 专业版的许可证将于 **YYYY-MM-DD** 到期。
> 到期后商业功能会降级为社区版（本地数据与任务不受影响），
> 续费后新的升级包拖入即可立即恢复。需要提前开票或调整席位请回复本邮件。

### 4.3 换机

> 您好，机器绑定版许可证与服务器的"本机指纹"绑定。请在**新服务器**打开
> 升级面板 →「本机信息」→ 复制「本机指纹」发给我们（16 位字母数字）。
> 我们会重新签发绑定到新机器的升级包；旧服务器如不再使用，请一并告知以便吊销。

### 4.4 激活失败排查（按面板提示对照）

| 面板提示 | 回复话术 |
|---|---|
| 签名校验未通过 | 请确认复制了**完整一整行**（以 `AMP2-` 开头）；仍失败请重新下载升级包核对 sha256 |
| 已过期 | 许可证已于 X 到期，续费后发新包 |
| 尚未生效 | 该证 X 日生效，旧证可继续用到 X-1 日 |
| 机器不符 | 见 §4.3，需重发绑定证 |
| 已被吊销 / 请联系发行方 | 转商务处理 |
| 缺少验签公钥 | 扩展包不完整（旧包/损坏），发同版本 `.ampkg` |
| 扩展包版本不一致 | 主程序与扩展包不同号，发同号 `.ampkg` |

## 5. 应急处理

### 5.1 客户许可证泄露（许可证原文外流）

1. 立即 `revoke <serial> --reason "leaked"`；
2. 把 CRL 打进新升级包，**要求客户更新**（或运维下发 CRL 文件）；
3. 给客户重发新证（新 serial）；
4. 记录到台账/事件单：泄露来源、时间、已影响机器。

> 吊销是离线的：必须把 CRL 送到客户机上才生效；没送到之前旧证仍能用。

### 5.2 退款 / 合同终止

1. `revoke <serial> --reason "refund"`（按台账 serial）；
2. 把 CRL 随下一批 `.ampkg` 分发或在客户配合下更新；
3. 台账标注退款日期（可在 `notes` 追加，不要删行）。

### 5.3 签发私钥疑似泄露

这是最高级别事件，按"宁可全部换证"处理（详见 `COMMERCIAL_ACTIVATION.md` §18.2）：

1. 立刻停止发证；
2. 发行技术执行紧急换钥：`keygen --force --write-public-key`（**不保留**旧钥）→ 重建 wheel → `doctor` 全绿；
3. 吊销泄露窗口内签发的证（`revoke` 全部相关 serial）；
4. 重发全部客户新证，台账记录"密钥轮换批次"；
5. 复盘私钥暴露路径（工单/聊天/截图/仓库/备份）。

### 5.4 wheel / 升级包发错版本

- 现象：客户装包后仍然激活失败、面板提示"扩展包版本不一致/缺少公钥"；
- 处理：`doctor` 检查 `wheel_public_key_matches` / `bundles_activatable`，
  按输出重建 wheel 与 `.ampkg` 后重发；旧包收回（记录包 sha256 作废）。

### 5.5 CRL 误吊销（误操作）

1. 从 `dist/crl/license_crl.json` 删除对应条目（人工编辑，保留 JSON 结构）；
2. 重新分发修正后的 CRL / 重打 `.ampkg`；
3. 事件单记录：误操作人、受影响 serial、恢复时间。

> 不要"再签一份新证绕过 CRL"而不清理条目 —— 台账会留下两条同客户记录，后续审计无法解释。

### 5.6 时钟回拨/系统时间异常批量告警

- 常见于虚拟机快照回滚、主板电池失效、NTP 配置错误；
- 指导客户校正时间（Windows: `w32tm /resync`；Linux: `chronyc makestep`）；
- 校正后下一轮复检（默认 1 小时）自动恢复，无需重启；急用可重启服务立即恢复。

## 6. 台账字段字典（运营版）

| 列 | 运营含义 | 敏感级别 |
|---|---|---|
| `customer` | 客户标识（与合同一致） | 内部 |
| `tier` | PRO / ENT | 内部 |
| `expiry` | 到期日（`00000000`=永久） | 内部 |
| `issued` | 签发日 | 内部 |
| `serial` | 吊销/客服定位的主键 | 内部 |
| `machine` | 绑定指纹（空=不绑定） | 内部 |
| `seats` | 席位（0=不限） | 内部 |
| `license` | 许可证原文 | **机密**（等同激活凭证） |
| `wheel` | 交付的升级包文件名 | 内部 |
| `sha256` | 交付物摘要（完整性核对） | 内部 |
| `notes` | 备注（合同号/渠道/特殊约定） | 内部 |
| `created_at` | 记录写入时间 | 内部 |

## 7. 常用命令速查

```bash
# 环境自检（每月/每次发版必跑）
python pro/tools/issue_license.py doctor

# 单客户发证
python pro/tools/issue_license.py bundle PRO 20271231 acme \
    --serial ACME20260001 --machine 0123456789abcdef

# 批量发证 + 台账 + 包
python pro/tools/issue_license.py issue-batch --csv customers.csv \
    --out dist/licenses --bundles --wheel pro/dist/automind_pro-<ver>-py3-none-any.whl

# 吊销 / 查看
python pro/tools/issue_license.py revoke ACME20260001 --reason refund
python pro/tools/issue_license.py crl list
python pro/tools/issue_license.py crl show

# 校验一份证（客服排障）
python pro/tools/issue_license.py verify AMP2-...
```
