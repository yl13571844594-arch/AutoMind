# IM 机器人接入：本地 / 云电脑部署的连通方案（v1.11.7）

## 结论：用「长连接」，不用回调

本地电脑和大多数云电脑**没有公网 IP**（在 NAT / 运营商 / 云厂商网关后面）。回调（webhook）模式要求
飞书、钉钉、企业微信的服务器**主动访问你的电脑**，所以必须配公网地址、域名、内网穿透、证书、可信 IP ——
任何一环断了，机器人就"收不到消息"，而且很难排查。

**长连接模式反过来：由 AutoMind 主动连到平台**（一条出站 WebSocket），消息从这条连接推过来。
只要这台电脑能上网（能打开网页就行），机器人就能收发消息：

| | 长连接（推荐） | HTTP 回调 |
|---|---|---|
| 需要公网 IP / 域名 | ❌ 不需要 | ✅ 需要 |
| 需要内网穿透（frp / ngrok / cpolar） | ❌ | ✅ |
| 需要 HTTPS 证书 / 可信 IP | ❌ | 视平台而定 |
| 防火墙 | 只需允许出站 443（默认就允许） | 需要放行入站 |
| 断线 | 自动重连（1s → 60s 退避，无限重试） | 依赖穿透服务稳定性 |

三家主流平台都官方支持长连接，AutoMind v1.11.7 起默认使用：

| 平台 | 渠道 | 平台侧设置 | 填到 AutoMind 的凭据 |
|---|---|---|---|
| 飞书 / Lark | 飞书 | 事件与回调 → 订阅方式「**使用长连接接收事件**」，事件 `im.message.receive_v1` | App ID、App Secret |
| 钉钉 | 钉钉 | 机器人 → 消息接收模式「**Stream 模式**」 | Client ID（AppKey）、Client Secret（AppSecret） |
| 企业微信 | **企业微信智能机器人** | 工作台 → 智能机器人 → API 模式 → 连接方式「**长连接**」 | Bot ID、Secret |
| 微信公众号 | 微信（公众号） | 只支持回调 → 需要公网地址（见文末） | AppID、AppSecret、Token |

> 企业微信请选「企业微信智能机器人」渠道。「企业微信（自建应用）」只能回调，而且发消息还要求配置企业可信 IP，
> 本地部署几乎配不通。

## 操作步骤（以飞书为例，钉钉 / 企业微信同理）

1. 飞书开放平台创建企业自建应用 → 添加「机器人」能力 → 开通权限 `im:message`、`im:message.group_at_msg`、
   `im:message:send_as_bot`；
2. AutoMind：设置 →「🤖 机器人」→ 添加 → 飞书 → 接收方式选「**长连接（推荐）**」→ 填 App ID / App Secret → 保存；
3. 等「🔌 连接状态」变成 **已连接**（一般 1~3 秒）；
4. 回到飞书开放平台：事件与回调 → 订阅方式选「使用长连接接收事件」→ 保存（**飞书要求先有客户端连上才允许保存**，
   所以第 3 步要先做）→ 添加事件 `im.message.receive_v1` → 发布版本；
5. 在飞书里单聊机器人，或把它拉进群 @ 它，发一个任务试试。

设置页的「💬 测试对话」也会显示从平台收到的真实消息，可用来确认链路是否打通。

## 各平台 Markdown 渲染规则与差异（v1.11.14）

Agent 输出的是通用 Markdown，但各平台支持的语法并不一样。v1.11.14 起，回复在发送前会先经过
`automind/bots/md_format.py` 的适配层：**能渲染的保留，不能渲染的降级成可读文本，但绝不丢内容**
（URL、代码、表格里的每个单元格都会保留）。

| 渠道 | 标题 | 表格 | 代码块 | 图片 | HTML 标签 | 单条上限 |
|---|---|---|---|---|---|---|
| 飞书 | 卡片 header `plain_text`（去标记、≤60 字） | 转「逐行字段列表」`- **表头**：值` | 保留围栏 | 保留 | 去掉标签 | 20000 B |
| 钉钉 | markdown `title` ≤30 字（只取第一行） | 同上 | 保留围栏 | 保留 | 去掉标签 | 15000 B |
| 企业微信（自建应用） | 正文首行 `## 标题` | 转项目列表 | 转 `> ` 引用（逐行保留代码） | 转链接 | 去掉标签 | 2048 B（按 2000 B 预留） |
| 企业微信（智能机器人，长连接） | 正文首行 `## 标题` | 转项目列表 | 保留围栏 | 转链接 | 去掉标签 | 20480 B（按 20000 B 预留） |
| 微信公众号 | `【标题】` | 转 `• 表头：值 · 表头：值` 纯文本 | 去围栏、保留代码原文 | `图片：说明（url）` | 去掉标签 | 约 2048 B（按 1900 B 预留） |
| 通用 Webhook | 原样放进 `title` 字段 | 原样 | 原样 | 原样 | 原样 | 60000 B |

补充说明：

- **标题**：飞书 / 钉钉用平台独立字段（飞书 header、钉钉 title），企业微信 / 公众号把标题放正文首行；
  钉钉 title 超过 30 字会加「…」，飞书 header 超过 60 字同理。
- **HTML**：只去掉标签、保留文字；`<a href="...">说明</a>` 会转成 `[说明](...)`，**href 地址不会丢**。
- **通用 Webhook** 不降级：原始 Markdown 原样透传给下游，由下游自己决定怎么渲染。

### 分片与续片规则

平台对单条消息有字节上限，适配层按下面的顺序处理（实现见 `md_format.split_message`）：

1. **先适配、再分片**：切的是「最终渲染文本」，避免先切后转导致表格 / 围栏被切开；
2. **优先在块边界断开**：空行、段落、标题、列表项、表格都是天然切点；
3. **绝不切在 ``` 围栏内部**；围栏代码块本身超长时，每一片都会自动补上开 / 闭围栏（不会漏出代码）；
4. 单块仍然超限时先按行切，单行还超限才按 UTF-8 字符硬切（中文一个字 3 字节，按字符边界切）；
5. 续片标题统一为 `标题（续 N/M）`（如 `周报（续 2/3）`），正文里不重复续片标记；
6. 标题会放在正文的渠道（企业微信 / 公众号）会先预留标题占用的字节；
7. 与旧版一致，单条消息最多连发 **6 片**以防触发平台限流，超出部分不再发送并记 `bot_message_truncated` 日志。

### 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 飞书里表格变成一串 `- **项目**：构建` | 正常降级：飞书卡片表格渲染很差，统一转成逐行字段列表，信息不丢 |
| 企业微信里代码块变成 `> 代码块（python）：` 开头 | 正常降级：自建应用不认围栏，转成引用块保留代码内容 |
| 公众号里看到「加粗没了」 | 公众号只能发纯文本，标记会被去掉、文字和链接地址都保留 |
| 代码块被拆成好几条消息 | 单条字节上限是平台限制；每片围栏都会补齐，顺序发送即可正常阅读 |
| 只收到前 6 条消息 | 防止触发平台限流；控制输出长度，或把结果写进文件用 /apply 交付 |
| 标题末尾出现「…」 | 钉钉 30 字 / 飞书 60 字是平台标题长度限制，正文不受影响 |
| 公众号里超大表格还看到 `\|` 竖线 | 表格本身超过单条上限被拆开，降级只对完整表格生效；各行内容仍在，建议改成列表 |
| Webhook 收到的还是原始 Markdown | 通用 Webhook 渠道有意不降级，由下游自行渲染 |

相关实现与测试：`automind/bots/md_format.py`、`tests/bots/test_md_format.py`。

## 连不上时怎么查

「🔌 连接状态」里会显示失败原因，常见的：

| 显示 | 处理 |
|---|---|
| 获取飞书长连接地址失败 / 钉钉 Stream 连接注册失败 | App ID / Secret 填错，或应用没开通机器人能力 / 没发布 |
| 企业微信智能机器人鉴权失败 | Bot ID / Secret 不对（Secret 只显示一次，丢了要在企业微信里重置） |
| 断开，自动重连中 | 网络中断或代理不通；恢复后会自动连上，也可以点「↻ 立即重连」 |
| 凭据未填写完整 | 按提示补齐必填项 |

公司网络需要代理时，设置系统环境变量 `HTTPS_PROXY` 后重启 AutoMind。

## 微信公众号 / 通用 Webhook：仍需公网地址

公众号只支持回调。可选方案：

- **cpolar / 花生壳 / natapp**（国内，最省事）：把本机 AutoMind 端口（默认 8765）映射成一个 https 地址，
  填到机器人配置的「公网地址」；
- **frp**：有自己的云服务器时最稳定；
- **cloudflared tunnel**：境外访问友好。

个人微信没有官方机器人接口，可以用 wechaty 等框架收消息，转发到「通用 Webhook」渠道。
